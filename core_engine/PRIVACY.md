# Privacy Policy

Effective date: 2026-06-01

This is a founder draft for GitHub publication and should be reviewed by qualified counsel before commercial sale.

## Overview

AnarchI Core is designed to be privacy-first. The core engine is intended to run locally and headlessly, with no telemetry enabled by default.

## Information The Core Engine May Process

Depending on configuration, AnarchI Core may process:

- Host resource information such as operating system, architecture, CPU thread count, available memory, and executable integrity hashes.
- Workload targets such as URLs, local executable paths, workload profiles, and resource requirements.
- Plugin manifests, plugin metadata, and plugin permission declarations.
- Cloud provider configuration needed to allocate or release remote resources.
- Logs generated by local engine operations.

## Information Not Collected By Default

AnarchI Core does not intentionally collect or transmit personal information by default.

The core engine should not transmit telemetry, analytics, crash reports, API keys, plugin data, or workload details unless a user or administrator explicitly enables a provider, integration, marketplace feature, support workflow, or future telemetry option.

## Credentials

Provider API keys and secrets should be handled through environment variables, operating system keychains, or other secure secret storage. Credentials must not be logged, committed to source control, embedded in packaged builds, or exposed to plugins unless explicitly authorized by policy.

## Cloud Providers And Plugins

When cloud bridge providers or marketplace plugins are enabled, those third parties may process data according to their own terms and privacy policies. Review provider and plugin policies before enabling them.

## Logs

Logs may contain operational information such as trim actions, bridge requests, provider names, target paths, and error messages. Production logs should redact secrets and avoid storing sensitive workload content.

## Data Retention

Local logs and configuration files remain on the user's machine unless the user or administrator chooses to transmit them. Retention periods may depend on operating system settings, product configuration, support workflows, or enterprise policy.

## Security

Please report security issues privately using the process in `SECURITY.md`.

## Changes

This policy may change as the product develops. Material changes should be documented in release notes.
